# NKAI Studio — Cloudflare Workers deployment

The main Studio is a full-stack TanStack Start/Vite application. Deploy it as a **Cloudflare Worker**, not as a static Pages upload. The existing `gateway/` Worker is a separate avatar-signalling service and does not host the Studio.

## Repository changes

- Root `wrangler.jsonc` supplies the Cloudflare Worker name, compatibility date, Node compatibility, and observability settings.
- The existing `NITRO_PRESET` override is used to build Nitro's `cloudflare_module` output.
- The 35 MiB MPFB CC0 sample is loaded from its upstream source rather than bundled as a Worker static asset, because Cloudflare caps individual assets at 25 MiB. The smaller brunette sample remains bundled and is non-commercial only.
- `.github/workflows/cloudflare-workers-build.yml` builds the app and validates the generated Worker bundle without deploying.
- `.github/workflows/deploy-cloudflare-studio.yml` is a manually triggered production deployment workflow. It requires real production credentials and runs database migrations before deployment.

## GitHub Actions secrets required for deployment

In **Repository → Settings → Secrets and variables → Actions**, create these repository secrets:

| Secret | Purpose |
| --- | --- |
| `CLOUDFLARE_API_TOKEN` | Cloudflare API token with permission to deploy Workers and manage Worker secrets |
| `CLOUDFLARE_ACCOUNT_ID` | Cloudflare account ID for that token |
| `NKAI_DATABASE_URL` | Production PostgreSQL connection string, preferably a provider's pooled endpoint |
| `NKAI_BETTER_AUTH_URL` | Final HTTPS origin of the Studio Worker, without a path, query, or trailing slash |
| `NKAI_BETTER_AUTH_SECRET` | Long, random Better Auth secret; keep it private |
| `NKAI_GOOGLE_CLIENT_ID` | Google OAuth client ID |
| `NKAI_GOOGLE_CLIENT_SECRET` | Google OAuth client secret |

Do not commit these values or paste them into issues. The workflow deliberately fails before building if any required secret is missing.

## Google OAuth

The Google OAuth client must allow the final Worker origin and the Better Auth Google callback URL generated by this app. Configure the authorized redirect URI to match the app's actual Better Auth callback route; verify it against the deployed auth configuration before testing sign-in.

## Run the deployment

1. Merge the Cloudflare deployment PR into `main`.
2. Add all required Actions secrets.
3. Open **Actions → Deploy NKAI Studio to Cloudflare Workers → Run workflow**.
4. Inspect the job logs. The workflow runs `npm run build`, applies migrations to the configured PostgreSQL database, deploys the Worker, adds runtime secrets, and checks the homepage response.
5. Check sign-in and app-specific server functions separately. An HTTP 200 homepage alone does not prove that OAuth, database writes, AI streaming, or WebRTC avatar media work.

## Important runtime validation

This is deployment automation, not a claim that every existing Node-specific server dependency is already compatible with Workers. In particular, this repository currently initializes authentication configuration from `process.env` at module scope and uses `pg` for PostgreSQL access. Cloudflare Worker environment bindings and outbound database connectivity must be verified in the deployed runtime. The build workflow catches compilation/bundling problems; it cannot prove production OAuth or database connectivity without valid secrets and a live deployment.

The LiveTalking GPU host remains a separate prerequisite for live video/audio. The gateway can be healthy while no GPU host is registered.
